Three things follow:

- **omnetpp was never the wrong workload.** The paper's own set-imbalance evidence (Figure 4) is

- **sjeng is the interesting signature**: 8× the capacity buys 1 point. Its misses are not capacity
  misses. 2017's descendant is `531.deepsjeng_r`.
- **milc and libquantum are pure streaming** — ~74% at both sizes. Nothing for SBC to balance.
- Paper's own headline gain: **9.2% / 12.8% miss reduction, 2.7–5.25% IPC, 0.31% / 0.58% area.** SBC was
  never a large-margin technique.

## 2. M18 gap 1 — CONFIRMED in the RTL

The saturation counter's only input is the directory tap, [Directory.scala:314](../../design/craft/inclusivecache/src/Directory.scala#L314):

```scala
io.tap.valid := ren2 && !internalRead
```

`ren2` is **any** directory read. Only SBC's own internal reads are excluded. So **inner-C write-backs
and X-channel flushes update the saturation counters** — and a write-back to a resident line reads as a
**hit**, cooling that set by 1. Our own terminology file lists both as *"Not accesses"*; the paper says
the counter moves "each time the set is accessed".

**Measured, 2026-09-26 board run:**

| | |
|---|---:|
| `L2_Accesses` (all directory lookups — what the tap sees) | 6,270,326,354 |
| `L2_AccessA` (real CPU requests) | 4,931,117,515 |
| **Non-accesses driving the saturation counters** | **1,339,208,839 = 21.4%** |

**Why it matters, and why it hits omnetpp and not calib.** A cooled set looks like a better migration
*destination* (`sat < T_lo`) than it is — the same failure mode as "full but always hits looks coldest",
now amplified. Rocket drops clean L1 victims silently, so inner-C Releases are mostly dirty write-backs:
omnetpp moved **514 M** dirty blocks, `l2_miss_calib` a few thousand. **The instrument the envelope was
measured with is barely polluted; the real workload is heavily polluted.**

**The fix is small** and follows an existing template exactly — one field on `DirectoryRead`, one
pipeline line, one condition on the tap, one drive at the single call site
(`Scheduler.scala:451-479`, where `isDemandA` already exists at line 700). One real design call: whether
an MSHR's *re-read* of the directory should tap, or only the allocating read (a re-read would
double-count one access).

**Falsifiable:** fixing it should move omnetpp's migration count and parked population a lot, and
calib's hardly at all. Testable in Verilator before any bitstream.

## 3. Two tracker rows were wrong

- **M16 is fixed.** The row said `Scheduler.scala:689-693` ORs the erase pulses and `Mux1H`es the home
  set. That code is gone: `Scheduler.scala:752-756` latches each MSHR's erase **with its own home set**
  in a per-MSHR pending slot (`grantOnePerCycle`, `:669-684`) and drains one per cycle, with an assert on
  the only remaining loss case. Fixed by 007 c0; the row was never updated. `PerfCounters` still moves
  the global level by `PopCount`, which is correct.
- **Task 005 is half done, not unstarted.** Commits 0 (`a1f4cbd`) and 1 (`b3bd6e4`) landed — every
  counter in `PerfCounters` behind one flag, plus the eight terminology counters (`0x3F0`–`0x428`),
  `PopCount` fan-in and `L2_StatsHold`. Commits 2 and 3 (three counter fixes, interval sampler) are not
  started, which is why **M8 and M15 are still open**.
- Consequence: **M5 is done** — a hit rate may now be quoted from the exact counters. The §0 line saying
  "do not quote a hit rate" is superseded.

## 4. Four claims corrected

Recorded so they are not re-derived:

| Claim | Correction |
|---|---|
| "Chase a bigger L2 so SPEC becomes viable" | Backwards — a bigger cache raises the baseline and shrinks what SBC feeds on. Capacity is SBC's *competitor*. The paper's claim is that SBC beats **more associativity**, at 0.5% area |
| "Our implementation is faithful to the paper" | Thresholds yes (T_hi = 31, T_lo = 16, verified in `Configs.scala`). **Inputs no** — see §2 |
| "No counting bug; the mismatch is in the workload" | Outcome counters are exact. The **decision-side** input is defective, and it is part of the calib/omnetpp mismatch |
| The 2 MB 8-way figure, asserted before opening the PDF | Correct, but stated with more confidence than the evidence then supported. Now verified — §1 |
