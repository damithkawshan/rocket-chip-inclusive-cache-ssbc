## 1. What we set out to do

Amendment 11 is a **bug hunt**, not a feature build. Instead of a crafted unit test, use a benchmark
that (a) carries its own end-to-end correctness oracle and (b) exercises the serve path naturally, so
the shadow checker localizes any fault to the exact cycle. Correctness only — no perf, no multi-core.

---

## 2. How we did it (all additive — no RTL `src/` logic change)

1. **New config `VerilatorRocket8KL116KL2SbcShadowConfig`** — standard SBC config + `sbcShadow=true`
   + `sbcDebug=true`, natural migration (no forced destination). Arms the BankedStore wrong-row model
   and the Directory `homeShadow` model.
2. **Counter prints** added to `sw/tmp.c` and `sw/matmult_float.c` — each includes `sbc_mmio.h` and
   prints the full SBC counter line **after** the checksum/verify, so the MMIO reads cannot perturb
   the data or the checksum.
3. **Oracle** captured: `tmp.c` on `NoSbcConfig` → checksum `0xb4777fc5`. (SBC regs read a tie-down 0
   with SBC off — mapped unconditionally in `Control.scala`, so no hang.)

---

## 3. The blocker we hit, and the one knob we turned

First `tmp.c` run migrated **once in 4.1 M cycles**. The workload was not the problem — the
**threshold** was. `WithInclusiveCache` auto-derives `migrationThreshold (T_hi) = 2*nWays-1 = 15`,
which equals `satMax`, so a set migrates only when its saturation counter is pinned at the ceiling
(15 net misses on 8 sets) — a bar a benign matmul essentially never clears. Elaboration confirmed
`T_hi=15 T_lo=8`.

Fix (a **cache-configuration** change): `SbcShadowConfig` now sets `migrationThreshold=4,
migrationClearThreshold=2` — migrate after a few net misses. `tmp.c` is left **unchanged**, so its
checksum oracle still validates the migrated data byte-for-byte. This is authoring the run so the
scenario *occurs* — not tuning to force a matching checksum (which the task forbids). After the change
elaboration read `T_hi=4 T_lo=2`.

BRANCH reachability printed on every build: `p=false m=true r=false b=false` → `secPerm=0` is correct
by construction on this platform.

## 5. The one path still cold — `dispRelease = 0` (dirty-parked writeback)

Not a bug — **structural for matmul**. A parked line only turns dirty if the CPU **writes** it while
parked (`secWrite` must fire first; it was 0). matmul's migrated lines are `A`/`B`, which are
**read-only** in the kernel — they are exactly the lines re-read as the 53 secHits — while `Res` is
written once at allocation and never migrated-then-rewritten. So `secWrite → dispRelease` cannot fire
under matmul, at any threshold or forced destination. Reaching it needs a **write-heavy** workload, the
directed GATE-5 cases S6/S7, or §10.10 dirty-source migration. Flagged, not worked around.

---

## 6. Method notes

- **Additive-only edits.** New config + two `printf` blocks after the checksum. No RTL `src/` logic
  touched — a shadow firing was to be reported and decoded, not coded around.
- **"Make the scenario happen" ≠ "force the answer."** Lowering the migration threshold makes
  migrations occur; the checksum oracle (`tmp.c` unchanged) still independently proves the data.
- **Direct sim invocation vs `make run-binary`.** Editing `RocketConfigs.scala` invalidates the make
  timestamps, so a `run-binary` on an old config would silently re-elaborate it — kept in mind when
  ordering the oracle run.
