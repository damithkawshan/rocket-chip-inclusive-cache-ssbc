# First FPGA A/B measurements, and why the hit-rate numbers cannot be trusted yet

**Dates:** 2026-09-09 → 2026-09-10
**Branch:** `sbc-sampling` (cut from tag `sbc-baseline-not-verified-2026-09-09` = `d8671cf`)
**Board:** VCU118, 50 MHz, 1 Rocket core, 8 KB L1s, 256 KB 16-way L2 (256 sets), Linux from SD.

Three things happened: the SBC/NoSBC bitstream pair was rebuilt and measured for area and timing,
the first real A/B latency numbers were taken on hardware, and an RTL audit found that **the
hit/miss counters both configs report are systematically wrong**. The last item is why the
performance numbers here are recorded as provisional.

Design plan for the fix: `coder/005-hit-accounting-and-sampling/`.

---

## 1. The headline: our hit rate is not a hit rate

`L2_Accesses` / `L2_Hits` increment in `Directory.scala` on `io.result.valid && !internalRead`.
The Directory sees every lookup but **not which channel it came from**, so the counter folds in
traffic that is not program traffic at all.

| Defect | Effect |
|---|---|
| C-channel Releases counted as accesses | A Release is a **guaranteed hit** (`MSHR.scala` asserts `new_meta.hit` on that branch — inclusion means the L1 can only release a line the L2 holds). Every one adds +1 to numerator *and* denominator, dragging the rate toward 100%. |
| X-channel flushes counted as accesses | Not program traffic. |
| Repeat-path hits invisible | A reload whose tag already matches never reads the directory, so a guaranteed hit is never counted. Undercounts hits. |
| Permission upgrade counted as a hit | BRANCH→T fires `s_acquire` and pays a full outer round trip, but the directory said "hit". |

**The `TL_signal_analysis` branch is not a usable reference either** — its three counters
(`TLDirMonitor`, `PerfProbe`, `SaturationCounter`) disagree with each other *and* with ours. The
TLD monitor filters to A-channel (better than us) but drops merged and reloaded requests, so its
denominator is too small. **Any cross-branch hit-rate comparison today is invalid.**

Fix is planned as two reported definitions, not one:
- **H1, no outer transaction** — `accesses` = inner-A requests accepted at entry, `misses` = outer
  Acquires issued. This is what a hit means for performance, and under SBC it is automatically
  right: a parked line served in place issues no outer Acquire.
- **H2, directory hit** — kept for continuity with earlier measurements.

## 2. Bitstream pair — area and timing

Built 2026-09-09 from identical RTL (`git diff 8ad5e29 d8671cf -- design/` is empty).
Both **met timing, 0 failing endpoints**.

| | NoSBC | SBC | Δ |
|---|---:|---:|---|
| Design WNS | +0.382 ns | +0.504 ns | both pass |
| Harness LUT | 60,887 | 72,064 | **+18.4%** |
| Harness FF | 42,362 | 48,423 | **+14.3%** |
| `l2` LUT | 7,276 | 18,686 | **+157%** |
| `l2` FF | 3,288 | 9,333 | **+184%** |
| `sbu` | — | 6,360 LUT / 5,666 FF | new |
| `dss` | — | 889 LUT / 130 FF | new |
| `mshrs_0..6` LUT | 1,596 | 5,546 | **+247%** |

`sbu`/`dss` are **absent** from the NoSBC build — the "zero hardware when disabled" rule holds on
real silicon, not just in sim.

**Critical path worth watching.** Design-level timing passes, but the core-domain worst path in the
SBC build is inside SBC and is deep:

```
sbu/dss/level_0_reg[2]/C  ->  sbu/parkCount_161_reg[1]/CE
60 logic levels, 5.924 ns logic (32% of the path), core-domain WNS 1.001 ns
```

18.6 ns of a 20 ns period. Fine at 50 MHz, would not survive a clock bump. It is combinational
depth, not a placement fluke — and it is the same DSS selection logic task 005 Step 3 touches.

The **+247% on the MSHRs** is the migration FSM replicated across all seven and is not called out
anywhere in the existing design docs.

## 3. memtest A/B — SBC loses

Pointer-chasing latency, ns/access, lower is better. **Single runs, unpinned, under Linux.**

| Working set | SBC | NoSBC | |
|---|---:|---:|---|
| 16 KiB | 459.12 | **368.12** | NoSBC 19.8% faster |
| 32 KiB | 592.56 | **431.00** | NoSBC 27.3% faster |
| 256 KiB | 1029.22 | **841.56** | NoSBC 18.2% faster |
| 512 KiB | **1521.52** | 1973.94 | SBC 22.9% faster |
| 4 MiB | 2040.32 | **1787.78** | NoSBC 12.4% faster |
| 16 MiB | 2449.36 | **2014.28** | NoSBC 17.8% faster |
| 64 MiB | 2731.70 | **2342.60** | NoSBC 14.2% faster |
| 256 MiB | 3018.24 | **2727.44** | NoSBC 9.6% faster |
| primary hit rate | 44.35% | **72.68%** | |

⚠️ **Do not quote the 512 KiB "win" without a repeat.** NoSBC's curve is non-monotonic there —
512 KiB (1973.94) is slower than 4 MiB (1787.78), which is physically impossible and means that
sample is noise. It lands on exactly the row where SBC appears to win.

Note the row labels are the benchmark's generic x86 names. This SoC has 8 KB L1s, a 256 KB L2 and
**no L3**: 16/32 KiB are already L2-resident, 256 KiB is at capacity, everything above is DRAM.

### Counter wrap — resolved with measurement

All SBC event counters are **32-bit and wrap silently** (`nSecMiss := nSecMiss + 1.U`, no
saturation). `L2_Accesses`/`L2_Hits` are 64-bit and irrelevant here.

| counter | measured rate | wraps in |
|---|---:|---:|
| secHits | 42,190/s | **28.3 h** |
| secMiss | 36,478/s | 32.7 h |
| attempted | 516/s | 2,313 h |

A 1-hour window uses ~3.5% of the range. Windows up to several hours are safe at these rates.

## 6. Bugs found in the measurement path

Each of these silently produced wrong or missing data, not an error.

1. **`rz -E` renames, it does not overwrite.** A second push leaves the OLD `sbc_read` in place and
   the new one as `sbc_read.0`, so `./sbc_read` runs the stale binary. Evidence was already in the
   tree: `...tlmon_520_360_5_10_d10_w10.txt.0` through `.3`. Now `rm -f` first, then verify `wc -c`
   against the host file size.
2. **`-noprog` measured whatever was loaded.** An SBC run was nearly filed as the NoSBC baseline.
   Now an identity check reads `migrations`/`parked` (0 by construction on NoSBC) and labels the run
   by what is *actually* on the board.
3. **UART has no flow control** — full-speed keystrokes drop characters, which turned `./sbc_read`
   into `./sbc_red`. Fixed with `send_slow` pacing plus echo verification.
4. **sudo timestamps are per-tty**, so `sudo -v` in the shell does not carry into expect's pty.
   Sidestepped entirely: the user is in `dialout`, so picocom opens the port without root.
5. **`set -u` breaks chipyard's `env.sh`** — its conda `activate.d` reads `$RISCV` before setting it.
6. **Boot timeout was a hard cap.** Now silence-based: every bootrom/kernel line resets the clock.
   A catch-all `-re ".+"` cannot be used for this — it always matches at offset 0 and would beat
   `login:`, since expect prefers the earliest-starting match.
7. **`scripts/logs/` was root-owned** from an earlier sudo run.

- 🟡 **Snapshot RAM readback** (task 005 Step 3, not built). Access is indexed — write `snapIdx`,

  auto-increments on read, saving a third of the bus traffic versus the TLD branch's version.

  climbing at window close), because `322494a` made parked lines last-priority for eviction and
  nothing repatriates them. Parked lines hold 44.0 % of the L2 and return 5.5 % of the hits —
  **13.6× less productive per line**. Isolating this is Stage 2 of the workplan.
