# Weekly report — 25 Sep 2026

**The week's result: we now know exactly when set balancing helps, and it is a rule with a number in
it.** It was confirmed on 78 of 80 measured points on the board. It also tells us that the work we have
been doing for three tasks was aimed at the wrong part of the design.

Audience: me and the supervisor. Full technical write-up:
[../performance/sbc-findings-2026-09-25.md](../performance/sbc-findings-2026-09-25.md).
Experiment record: [../performance/board-calib-envelope-2026-09-25.md](../performance/board-calib-envelope-2026-09-25.md).

## The rule

> Set balancing pays **exactly while a hot set's overflow fits the empty ways of its partner.**

In symbols, with `ways` = associativity: a hot set holding `MP` lines overflows by `MP − ways`; a cold
set holding `HP` lines offers `ways − HP` empty ways. It pays while

> `overflow ≤ empty ways`, i.e. `MP ≤ 2·ways − HP`

| | |
|---|---|
| Inside that region | up to **−41% cycles**, **−85% memory reads** |
| Outside it | up to **+14% cycles**, **+24% reads** |
| How often outside | **half** of the 80 points measured |
| Rule correct on | **78 of 80 points (98%)** |

The losing half matters as much as the winning half: outside the region, moved lines flood the partner
set and evict the lines that were hitting there. Being outside is not "no benefit" — it is a real loss.

![operating envelope](../performance/figs-calib-envelope-2026-09-25/envelope.png)

The black staircase is the formula, drawn from the model rather than fitted. The blue (faster) region
sits inside it.

## Why this explains everything we have measured since August

Our real workload — omnetpp on a 64 KB 16-way L2 — sits far outside that region. Its working set per
set is in the hundreds of lines against at most 16 empty ways. That is the corner of the map where the
measurement says **+13% cycles**, and it is exactly what we have been seeing.

So SBC has not been failing because of a bug in our rules. It has been running outside the conditions
the idea needs.

---

## Two things I had told you that were wrong

1. **"Hits per parked line is the figure of merit"** (0.47 on omnetpp against a break-even of 1.0).
   It is not. Among *winning* points that number runs from **0.19 to 295** — 0.47 sits inside the
   winning range.
2. **"The gain comes from reusing moved lines."** It mostly does not. **77% of the gain is the source
   set no longer thrashing** once its excess is moved out. Only 23% is serving the moved lines. The
   value is relieving the hot set, not finding lines in the partner.

Both corrections came from the same sweep, and both change what is worth building.

## The RTL work: task 012 finished, and it does not pay

Task 009's change hung the board (0 of 4 runs). Task 012 re-landed the safe half of it in stages.

| | Result |
|---|---|
| Simulation gate | green, including a directed test for the one dangerous untested path |
| Board gate | **4 of 4 runs completed** (009's image: 0 of 4) |
| Did the new path fire? | yes — dirty destination aborts **48,258 → 0** |
| Performance | **unchanged**: hit rate flat, cycles and traffic ~0.3% *worse* |

The fix does exactly what it was designed to do and buys nothing, because destination aborts were only
**1.8% of migration attempts**. Three tasks (009, 011, 012) went into the destination side; the sweep
shows the destination side was never where the performance was. That is a useful negative result, and
it was cheap to get once the right experiment existed.

## What I propose for next week

1. **Do not build 012 C3** (the remaining destination case). It is 45% of a slice worth under 2%, and
   it carries the exact deadlock shape that hung the board.
2. **Build the throttle.** The cache cannot tell a workload that fits from one that does not — it
   migrates either way, and in the second case it actively hurts. The job is now specific: *stop
   migrating when the overflow does not fit*. The RTL already distinguishes an **invalid** destination
   way from an **overwritten** one, which is the direct test for real free space.
3. **One cheap experiment first:** allow migration only into a genuinely invalid way, as a runtime bit.
   No new state, testable in simulation before any bitstream.
4. **Consider geometry.** The paper used 4096 sets and 8 ways; we use 64 sets and 16 ways, and the paper
   itself warns that fewer, larger sets leave less to win. A 128 KB L2 moves toward its regime.
